1. What is the most surprising difference between Python and Bash for you?
The most surprising difference is how they handle output and execution. 
Bash commands execute silently by default on success, only printing something if specifically asked (or if an error occurs). 
Additionally, everything in Bash is treated as text or strings, requiring explicit syntax like $(...) for command substitution. 
Python, on the other hand, is heavily object-oriented and strict about data types, 
requiring an explicit library (like 'subprocess') just to interact with the underlying operating system.

2. How does grep make log analysis faster than the Python scripts you wrote earlier?
Grep is a specialized tool written in highly optimized C that searches files directly at the system level. 
Instead of writing loops to open a file, read it line-by-line, and run string checks (like in Python), 
grep processes text blocks incredibly fast using optimized search algorithms. 
It allows us to filter or count complex patterns across massive log files in a single, lightweight command line.

3. What was the hardest concept to grasp (permissions, piping, subshells)?
Piping and command substitution were the trickiest concepts. 
Understanding how the | (pipe) character redirects the standard output (stdout) of one application 
to act directly as the standard input (stdin) of another takes a mental shift. 
It requires you to stop thinking of programs as standalone tools and start seeing 
them as modular LEGO blocks that pass raw data streams back and forth seamlessly.
